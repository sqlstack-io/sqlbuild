Checks that your project config is valid, the adapter is resolvable, and the warehouse connection works. Useful for diagnosing setup issues. It reads only the configuration, the adapter and the providers, so an error in a model,
macro or Python node does not stop it.

For detailed progress from any other command, use the global [`--debug`](/docs/cli/build#global-options) option instead, as in `sqb --debug build`.

## Usage

```bash
sqb debug [flags]
```

## What it checks

The command reports four groups of checks:

**Runtime** - SQLBuild version, Python version, Python path, OS info.

**Configuration** - Finds and validates `sqlbuild_project.toml`, loads `sqlbuild_local.toml` if present, shows the [env file](/docs/concepts/project-configuration#env-file) and how many variables came from it, resolves the adapter, active target, connection, database, and schema. For Snowflake it also shows the warehouse each [command group](/docs/concepts/adapters/snowflake#command-group-warehouses) connects with and where that value came from.

**Providers** - Counts the [providers](/docs/concepts/python-nodes/providers) whose [secrets](/docs/concepts/python-nodes/providers#secrets) are all set, and lists each missing secret as `WARN`. When every secret is set it prints one line. `--verbose` lists every provider and secret, and marks a secret the env file set as `set from env file`. Values are never shown.

```text
Providers:
  providers: 2 of 3 ready [WARN missing secrets]
  slack_alerts: SLACK_WEBHOOK_URL [WARN missing]
  more: sqb debug --verbose lists every provider [SKIP]
```

**Connection** - Displays connection settings as `sqb debug` itself uses them, with the `query` warehouse group applied (secrets are masked), attempts to connect to the warehouse, and runs `SELECT 1` to verify query execution.

## Flags

| Flag | Description |
|------|-------------|
| `--no-connection` | Skip the connection and query tests. Useful for validating config without warehouse access. |
| `--json` | Output results as JSON instead of formatted text, with `missing_secrets` counting the unset provider secrets and `history_reads_wake_compute` saying whether reading warehouse history starts billed compute. |
| `--verbose` | List every provider and secret setting, set or missing. |
| `--warehouse <name>` | Snowflake warehouse for this invocation; overrides the target's `query` [warehouse group](/docs/concepts/adapters/snowflake#command-group-warehouses) and the connection warehouse |

## Exit codes

Returns `0` when all checks pass, `1` when any check fails (e.g. connection refused, invalid config). A missing provider secret is a warning and doesn't fail the command.
A failed run is recorded in [Recall](/docs/concepts/observability/recall) with the first failed
check as its cause:

| `error_code` | `error_type` | Meaning |
|------|------|---------|
| `C980` | `ConnectionError` | The connection test failed |
| `C981` | `QueryError` | The connection worked but `SELECT 1` failed |
| `C982` | `ConfigurationError` | Another check failed, such as an invalid configuration file |
